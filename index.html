INTRODUÇÃO

Um projeto, diferentes perspectivas.

A Clínica Vida+ é um cenário fictício para integrar práticas de gestão de projetos e fundamentos de desenvolvimento de software. Cada etapa resolve uma parte do problema: organizar o trabalho, estruturar um cadastro e representar decisões e fluxos.

O quadro é uma demonstração local, e o programa Python funciona no terminal. Nenhuma parte desta aplicação deve receber dados pessoais ou médicos reais.

OBJETIVOS

O que vamos construir.

  • Planejar e acompanhar atividades em sprints.
  • Aplicar listas e dicionários em um cadastro Python.
  • Validar regras por meio da lógica proposicional.
  • Demonstrar a estrutura FIFO e modelar casos de uso.
CONCLUSÃO

Conhecimento conectado, do início ao fim.

O trabalho une planejamento, implementação e análise formal: a consulta normal é liberada em 3 combinações e a emergência em 6; a fila preserva a ordem de chegada e o diagrama explicita responsabilidades e funcionalidades obrigatórias.

REFERÊNCIAS E FERRAMENTAS

Para ir além.

Construído com HTML5, CSS3, JavaScript e Python 3; quadro armazenado no navegador e versionamento com Git.

PRÓXIMA ETAPA02 · Cadastro em Python
PASSO 02 / PROGRAMAÇÃO

Cadastro em Python.

Um programa de terminal de verdade, organizado com listas e dicionários.

Os registros ficam somente na memória durante a execução e são apagados ao sair. Use exclusivamente dados fictícios; o programa não é adequado a dados reais.

O PROGRAMA

O essencial, com clareza.

O arquivo clinica_vida.py usa uma lista de dicionários para guardar nome, idade e telefone de cada paciente. Seu menu permanece em execução até a opção de sair.

  • 01
    Cadastro validado

    Valida nome, idade inteira de 0 a 130 e telefone com DDD.

  • 02
    Estatísticas confiáveis

    Total, idade média e pessoas mais novas e mais velhas, inclusive empates.

  • 03
    Busca e listagem

    Busca parcial sem diferenciar maiúsculas ou acentos e trata resultados vazios.

Terminal · exemplo de execuçãoPYTHON 3
$ python3 clinica_vida.py

Use apenas dados fictícios. Os dados são apagados ao sair.

PASSO 03 / LÓGICA PROPOSICIONAL

Regras de atendimento.

Quatro condições, duas modalidades e todas as 16 combinações possíveis.

A

Tem agendamento

B

Documentos válidos

C

Médico disponível

D

Pagamentos em dia

MODALIDADE 01

Consulta normal

(A ∧ B ∧ C) ∨ (B ∧ C ∧ D)

3 de 16 situações liberam o atendimento.

MODALIDADE 02

Emergência

C ∧ (B ∨ D)

6 de 16 situações liberam o atendimento.

EXPERIMENTE

Analise uma combinação.

Alterne as condições para ver o resultado e localizar a linha nas tabelas.

V = verdadeiro  ·  F = falso
CONSULTA NORMALNão liberada
EMERGÊNCIALiberada
?
O caso solicitado: A=F, B=V, C=V, D=F

Consulta normal: F. O primeiro termo é falso porque não há agendamento (A=F); o segundo é falso porque os pagamentos não estão em dia (D=F). Emergência: V. O médico está disponível (C=V) e os documentos são válidos (B=V), portanto B ∨ D é verdadeiro.

Fila de pacientes.
